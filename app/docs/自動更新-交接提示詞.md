## 已經踩過的坑（請務必避開，這些是血淚）

1. **執行中的 exe 不能覆蓋自己。** Windows 會鎖住。更新流程一定要「下載到暫存 →
   關掉主程式 → 由一個小的外部程式（bat 或另一個 exe）完成置換 → 重新啟動」。
2. **絕對不要動使用者的校準與樣板。** 之前打包腳本用「檔案 mtime 誰比較新誰是母本」
   做雙向同步，結果把使用者逐格校準的五格手牌位置和 40 幾個自己抓的點數/花色樣板
   覆蓋掉了，而且備份只留一代又被下一次打包蓋掉，救不回來。
   **更新邏輯只能覆蓋程式碼，資料目錄一律不碰**，並且動之前先備份。
3. **虛擬環境搬過位置會讓 `Scripts\*.exe` 全部失效** —— 那些啟動器把建立當下的
   `python.exe` 絕對路徑寫死在檔頭。所以腳本裡一律用 `python.exe -m 模組名`，
   不要叫 `pip.exe` / `pyinstaller.exe`。
4. **設定檔升級**：`src/config.py` 有 `CONFIG_VERSION` 與 `RETUNED_ON_UPGRADE`
   機制，`_deep_merge` 補新欄位、必要時強制換掉重新調校過的參數，
   **但校準座標一律保留**。加版本號時請沿用這套，不要另外發明。
   注意：`RETUNED_ON_UPGRADE` 會強制覆蓋使用者調過的值，加項目要很克制。
5. `defaults/parts/` 是內建（比較模糊）的樣板，`card_templates/parts/` 是實際使用的。
   `load_part_templates()` 會**優先用使用者自己抓的**，同一個標籤有自己的就完全
   不用內建的。更新時不要把 `defaults/` 的東西複製進 `card_templates/` 覆蓋掉。
