# HoloTool 畫面辨識問題診斷報告

檢查範圍：`F:\holotool` 的 `src/`、`gui.py`、`config/config.json`、`card_templates/`、`defaults/ui/`、`logs/bot_2026-08-20.log`、`debug_captures/`（27 張 thumb 實機截圖）。

---

## 結論摘要

「有些畫面無法辨識」不是單一原因，是 **6 個問題疊在一起**。按影響程度排序：

| # | 問題 | 影響 |
|---|---|---|
| 1 | **一張卡牌樣板都沒有** | 手牌永遠 0/5、比大小永遠認不到牌 |
| 2 | **樣板是 1024×438 的預設圖，實機視窗是 1937×817** | 六個畫面標記全部失準 |
| 3 | `_search_score` 的縮放階梯最大只到 1.3×，跳過 1.89× | 放大視窗時「正確的比對尺寸從來沒被試過」 |
| 4 | padding 用「整個視窗」的比例，不是區域自身比例 | 搜尋範圍暴增 → 各標記互相誤判 |
| 5 | 對話框出現時牌桌 logo 被模糊 | 誤判「已離開牌桌」而自動停止 |
| 6 | `load_card_templates()` 把 UI 樣板當成卡牌載入 | 可能丟出例外，整個 tick 被吃掉 |

---

## 1. `card_templates/` 裡沒有任何一張卡牌樣板（最關鍵）

`F:\holotool\card_templates\` 和 `dist\HoloTool\card_templates\` 兩邊都只有 6 個檔案：

```
table_marker.png  ui_challenge.png  ui_congrats.png
ui_draw_prompt.png  ui_fail.png  ui_poker_fail.png
```

沒有 `AS.png` / `10H.png` / `QD.png` 這類牌面樣板。

`recognize.py` 的 `load_card_templates()` 因此回傳空的卡牌集合，`recognize_card()` 直接 `return None`。log 完全印證這點 —— 34 行紀錄裡每一行都是：

```
手牌=0/5 比大小=-
```

**後果**：`_handle_draw_phase` 和 `_handle_highlow_phase` 永遠不會被觸發，bot 只能在「待機點擊開始」和「失敗畫面點再一次」之間打轉。這就是為什麼看起來像「有些畫面認不出來」。

→ 必須執行 `collect_templates.py` 或用 GUI「卡牌樣板」分頁，把 52 張牌蒐集起來（至少常出現的那些）。

---

## 2. 樣板解析度（1024×438）和實機視窗（1937×817）對不上

`config.json` 記錄的校準尺寸：

```json
"calibration": { "client_width": 1937, "client_height": 817 }
```

但目前 `card_templates/` 裡的六張 UI 樣板，**與 `defaults/ui/` 的檔案 MD5 完全相同**（我逐檔比對過）。而 `src/defaults_layout.py` 開頭就寫著：

> 「從 1024×438 截圖量出來的預設框選」

樣板尺寸也印證：`table_marker.png` 是 148×80，剛好等於 `0.1445 × 1024` 和 `0.1826 × 438`。

也就是說，**目前跑的是內建預設樣板，不是你自己視窗擷取的樣板**，兩者差 1.89 倍。最可能的原因是校準後又按了「套用截圖預設框選」，那個按鈕會 `install_templates=True`，把樣板整組還原回預設。

### 實測數據

我把 27 張實機截圖分別 render 成不同解析度，跑現行的 `region_similarity()`：

| render 尺寸 | 選牌 (真陽性) | 過關 | 翻倍 | 失敗 |
|---|---|---|---|---|
| 512×219 | 0.74 | 0.52 | 0.79 | 0.92 |
| **1024×438**（樣板原生） | **0.90** | **0.97** | **0.92** | **0.99** |
| 1440×616 | 0.74 | 0.51 | 0.81 | 0.93 |
| **1937×817**（你的實機） | **0.61** | **0.48** | **0.54** | **0.72** |

門檻是 0.80。**只有在 1024×438 這個原生解析度下才過得了門檻；在你實際使用的 1937×817 下，六個標記全軍覆沒（0.45～0.78），沒有任何一個能被偵測到。**

## 3. 縮放搜尋的階梯有斷層（`recognize.py:93`）

```python
for scale in (0.45, 0.55, 0.7, 0.85, 1.0, 1.15, 1.3, max_scale):
```

`max_scale = min(iw/tw, ih/th)`，以「翻倍」標記為例約是 3.02。你需要的倍率是 `1937 / 1024 ≈ 1.89`。

階梯是 `... 1.15, 1.3, 3.02` —— **1.89 落在 1.3 和 3.02 中間的斷層裡，永遠不會被試到**。所以「縮放不變」這個設計在放大超過 1.3 倍之後就失效了。

---

## 4. padding 用整個視窗的比例（`state_machine.py:25`）

```python
def _expand_region(region, pad=0.05):
    x = region["x"] - pad          # pad 是「整個視窗寬」的 5%
```

在 1937 寬的視窗下，`pad=0.05` 等於左右各加 **97 px**；「失敗」標記用 `pad=0.12`，等於左右各加 **232 px**。搜尋範圍變成 752×293，拿一張 152×52 的樣板在裡面多尺度亂掃，找 `max()`，**必然掃出假陽性**。

log 裡這一行就是鐵證 —— 六個標記同時亮起來：

```
牌桌=76% 選牌=56% 過關=35% 翻倍=49% 失敗=72% 湊牌失敗=95%
```

另外 `region_similarity()` 回傳 `max(拉伸比對, 搜尋比對)`，其中「拉伸比對」是把樣板硬撐滿**已經加了 padding 的**整塊 ROI，結果完全沒有意義，只會把分數往上推。六個標記還共用同一個門檻 `table_marker_threshold = 0.80`。

### 修正後的驗證

我改成「padding 用區域自身尺寸（左右 ±35%、上下 ±90%）」＋「縮放集中在 視窗寬/樣板原生寬 附近 ±15%」，同一批 27 張截圖：

```
              真陽性最低   假陽性最高    分離度
過關 congrats     0.97        0.57       +0.39
翻倍 challenge    0.93        0.64       +0.28
失敗 fail         0.99        0.71       +0.28
牌桌 table        0.89        0.77       +0.12
```

而且 **1024 / 1440 / 1937 三種 render 尺寸的分數完全一致**，真正做到縮放不變。

## 5. 對話框出現時牌桌 logo 被模糊 → 誤判「已離開牌桌」自動停止

`bot.py:229` 的邏輯：連續 8 個 tick（0.4s × 8 = 3.2 秒）沒看到 logo，就判定達到每日上限並停止。

但實機截圖顯示，只要「成功！」「翻倍機會！」「無對子」這類對話框跳出來，**整個牌桌背景（含左上角 High&Low logo）都會被遊戲加上模糊**。我量到的分數：

| 畫面 | table_marker 分數 |
|---|---|
| 投注 / 選牌 / 比大小（正常牌桌） | 0.89 ～ 0.96 |
| 翻倍・成功對話框（41f6725f / 42179c70 / 99861c8c / a4e7b202） | **0.63 ～ 0.69** |
| 湊牌失敗（4ed2c2fc / 875d10c9 / 6ab4b108） | **0.71 ～ 0.79** |

對話框停留超過 3.2 秒就會被誤判成「已達每日上限」而自動停機。

→ 修正方向：只要任何一個對話框標記（congrats / challenge / fail / poker_fail）成立，就把 `_missing_table_ticks` 歸零；並把 8 tick 拉長到 20 以上。

## 6. `load_card_templates()` 誤把 UI 樣板當成卡牌（`recognize.py:30`）

```python
base_name = name.split("_")[0]
if base_name.lower() in RESERVED_NAMES or base_name.lower().startswith("ui_"):
    continue
```

- `ui_congrats` → `split("_")[0]` = `"ui"` → `"ui"` 不在 `RESERVED_NAMES`，也不是以 `"ui_"` 開頭 → **沒被過濾掉**
- `table_marker` → `"table"` → 同樣沒被過濾掉

實際執行結果：

```python
>>> load_card_templates('card_templates')
{'ui': 5, 'table': 1}      # 6 張 UI 圖被當成 2 張「卡牌」
>>> Card.from_label('ui')
ValueError: 無法解析卡牌標籤: UI
```

一旦某個手牌格的畫面和某張 UI 圖相似度超過 0.83，`recognize_card` 就會回傳 `"ui"`，接著 `Card.from_label("ui")` 丟出 `ValueError`，被 `bot.py:157` 的萬用 `except` 吃掉，只在 log 印一行「[錯誤] 主迴圈發生例外」，整個 tick 作廢。

→ 修正：改成比對整個檔名（`name.lower() in RESERVED_NAMES or name.lower().startswith("ui_")`）。

## 其他一併發現的問題（影響較小）

### A. 「湊牌結果」畫面的標題是會變的

實機截圖顯示同一個版面的標題有至少三種：

- `thumb_4ed2c2fc` → **無對子**
- `thumb_875d10c9` → **一對**
- `thumb_6ab4b108` → **失敗**（這是比大小輸掉）

`ui_fail.png` 只有「失敗」兩個字，所以「無對子」「一對」這兩種畫面用 `fail_marker` 一定認不出來。三種畫面唯一不變的是副標 **「要再玩一次撲克嗎？」**（`poker_fail_marker`，框選位置正確）。

→ 應該以 `poker_fail` 為主判斷，`fail` 只當作「比大小輸了」的補充資訊。

### B. `fail_marker` 框選位置偏上

在 `thumb_4ed2c2fc` 上量測，「無對子／失敗」的文字下半部落在框外，框內大部分是模糊背景。建議往下修 3～5%。

### C. 大／小按鈕的點擊座標貼在按鈕右緣

實測「太大」按鈕橫跨 x = 0.667 ～ 0.833，「太小」是 0.667 ～ 0.837。

設定檔是 `high_button.x = low_button.x = 0.8281` —— 距離右緣只剩 0.005（1937 寬的話約 9 px）。稍微有點誤差就點空了。

→ 建議改成 `x = 0.75`（按鈕正中央）。y 方向：太大約 0.46、太小約 0.59，目前的 0.4566 / 0.5753 沒問題。

### D. 比大小的歷史牌是重疊堆疊的，整張卡面比對不會成功

`thumb_0aa343d3`、`thumb_ebcd20fe` 顯示，比大小畫面左側的歷史牌是層層疊在一起的，每張只露出**左上角的點數＋花色**，牌面主圖被下一張蓋住。

`_recognize_highlow_card()` 目前是用「整張卡面」樣板去滑動比對，就算把 52 張樣板都蒐集齊了，這些被遮住的牌一樣認不出來。

→ 需要改成只比對「左上角點數＋花色」那一小塊。

## 建議的處理順序

1. **蒐集卡牌樣板**（問題 1）—— 沒有這個，bot 只是在空轉。
2. **在你自己的 1937×817 視窗重新擷取六個 UI 標記樣板**（問題 2）
   —— GUI「校準」分頁 → 逐項重新框選，框完當下就會存樣板。
   **⚠️ 之後不要再按「套用截圖預設框選」**，那會把樣板整組蓋回 1024 的預設圖。
3. **改 `recognize.py` / `state_machine.py`**（問題 3、4、6）—— padding 改用區域比例、縮放範圍改成由「視窗寬 ÷ 樣板原生寬」推算、六個標記各自獨立門檻、修掉 UI 樣板誤載入。
4. **改 `bot.py` 的離桌判斷**（問題 5）—— 對話框成立時重置計數器。
5. 微調 `fail_marker` 框選位置與大／小按鈕座標（B、C）。
6. 改比大小的角落比對（D）。

第 2 步做完之後，就算程式一行都還沒改，六個畫面標記的辨識率應該就會明顯回升 —— 因為樣板尺寸終於和實機一致了。
