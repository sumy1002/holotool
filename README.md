# HoloTool — Hololive Dreams「High & Low」自動遊玩工具

這是一個針對《ホロライブドリームス》(Hololive Dreams) 裡的小遊戲
**High & Low（カードオブグリード）** 設計的螢幕監測自動化工具。

流程對應遊戲玩法：

1. **門票關卡**：發 5 張牌，選擇保留/更換，換牌後至少要湊到「兩對」才能拿到門票，
   進入比大小環節（未達標則這次下注失敗）。
2. **比大小關卡**：亮出一張牌，猜下一張會「比較大」還是「比較小」，猜對就加倍，
   可以選擇繼續加倍或收手兌現。
3. **每日上限**：金額翻倍超過上限（約 12800 硬幣）時，遊戲會強制結束該輪並顯示
   「已達最高獲得金額，遊戲結束」。這個上限**每天可以達成兩次**：
   - 第 1 次：畫面停在結算頁，按「再玩一次」還能玩第二輪
   - 第 2 次：遊戲直接關掉牌桌，今天就到此為止

工具會：按下 **F9** 後開始自動判斷、自動玩，並持續記錄「今天看過的牌」來估計機率，
用來決定選牌/比大小的最佳策略；偵測到被踢出牌桌畫面（=可能已達每日上限）時自動停止。

> ⚠️ **使用須知**：對遊戲畫面進行自動化操作，可能違反遊戲的服務條款，有帳號被
> 處分的風險，請自行評估後使用，本工具僅供個人研究/省力用途。另外因為我沒有你
> 實際的遊戲畫面，下面列出的「假設」很可能需要你依實際狀況調整（見下方「已知假設」）。

## 目錄結構

最外層只有四樣東西，其餘全部收在 `app\` 裡面。

```
holotool/
  gui.py                   # ★ 程式本人。雙擊 exe 或跑原始碼都是從這裡進
  README.md
  requirements.txt
  app/                     # 其餘全部在這裡
    src/                   #   主要程式邏輯
      version.py           #     ★ 版本號的唯一來源 + GitHub repo 位置
      updater.py           #     檢查更新 / 下載 / 驗證 / 備份 / 置換
    tools/                 #   命令列輔助工具
      run_bot.py           #     主程式（命令列版），按 F9 啟動/停止
      calibrate.py         #     校準工具（命令列版）
      collect_templates.py #     整張卡面樣板擷取（備援用）
      check_setup.py       #     狀態檢查：一眼看出校準到哪一步、還缺什麼
      check_markers.py     #     離線檢查：拿截圖算出畫面標記各拿幾分
      promote_templates.py #     把自己抓的樣板複製進 defaults/（進版控用）
      _bootstrap.py        #     讓子資料夾裡的工具找得到 src 套件
    packaging/             #   打包相關，平常用不到
      build_exe.py         #     打包成 app/dist/HoloTool/HoloTool.exe
      build_installer.py   #     一鍵產生給別人的 app/dist/HoloToolSetup.exe
      make_release.py      #     產生 GitHub Release 用的更新包 + SHA256
      make_icon.py         #     icon.png → icon.ico（多尺寸）
      icon.png             #     程式圖示的來源圖，換圖直接換這個檔
      HoloTool.iss         #     Inno Setup 安裝程式腳本
      tidy_project.py      #     把最外層整理乾淨（可重複執行）
      repair_venv.py       #     修好「搬過位置」的虛擬環境
    docs/                  #   文件
    tests/                 #   測試
    config/config.json     #   校準結果會存在這裡
    card_templates/        #   畫面標記樣板
      parts/               #     點數 / 花色小樣板（辨識牌面用，13 + 4 個）
    defaults/              #   內建預設樣板，第一次執行會自動複製到上面
    data/                  #   每日出牌統計紀錄（自動產生）
    backups/               #   更新前的校準/樣板備份（自動產生，留最近 5 份）
    logs/                  #   執行紀錄（自動產生）
    debug_captures/        #   除錯截圖（自動產生）
    dist/                  #   打包產物（自動產生）
    .venv/                 #   虛擬環境
```

幾個重點：

* **`gui.py` 不吃資料夾名字。** 它會自己找「裡面有 `src\paths.py` 的那個子資料夾」，
  所以你想把 `app\` 改成別的名字也不會壞。
* 所有指令都在**專案根目錄**下，以 `app\` 開頭，例如
  `app\.venv\Scripts\python.exe app\tools\check_setup.py`。
* 打包成 exe 之後結構會變平（`HoloTool.exe` 旁邊直接是 `config\`、`card_templates\`），
  這是刻意的 —— 拿到安裝檔的人不需要看到原始碼的分層。

## 安裝

已內建一個虛擬環境 `app\.venv`，若要重新安裝：

```powershell
cd F:\holotool
python -m venv app\.venv
app\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

> 舊版的 `.venv` 在最外層。跑過 `app\packaging\tidy_project.py` 之後它會被搬進
> `app\`；如果搬不動（你正在用它跑腳本，Windows 會鎖住），腳本會產生一個
> `move_venv.bat`，關掉終端機再雙擊它就好。

> ⚠️ **虛擬環境搬過位置之後，`Scripts\` 底下那些 `.exe` 會壞掉。**
> `pip.exe`、`pyinstaller.exe` 這些其實是很小的啟動器程式，**把建立當下的
> `python.exe` 絕對路徑寫死在檔頭**。整個 `.venv` 一搬家，它們就會去找一個
> 已經不存在的路徑，執行起來只丟一個結束碼 1 —— 看起來像 PyInstaller 壞了，
> 其實是啟動器壞了。
>
> `python.exe` 本身不受影響（靠旁邊的 `pyvenv.cfg` 定位），所以：
>
> * **平常一律用 `python.exe -m 模組名`**，例如 `python.exe -m pip install ...`。
>   打包腳本現在也都改成這樣，不會再踩到。
> * 想把那些 `.exe` 修回來（這樣才能直接敲 `pip install`）就跑一次：
>   `app\.venv\Scripts\python.exe app\packaging\repair_venv.py`

> `keyboard` 套件在 Windows 上要監聽全域熱鍵，某些情況下需要「以系統管理員身分」
> 執行終端機才能正常運作，若按 F9 沒反應，請改用系統管理員權限重開終端機再試。

## 快速開始（推薦：直接雙擊 exe）

打包完成後，雙擊下面任一處即可開啟，不必再打指令：

- `app\dist\HoloTool\HoloTool.exe`
- 桌面上的 `HoloTool` 捷徑

若還沒打包，或想重新產生 exe：

```powershell
cd F:\holotool
app\.venv\Scripts\python.exe app\packaging\build_exe.py
```

設定檔、卡牌樣板、統計都會存在 **exe 同一個資料夾**（`app\dist\HoloTool\`），不要只複製 exe 單檔到別的地方。

開發時也可以直接跑原始碼：

```powershell
cd F:\holotool
app\.venv\Scripts\python.exe gui.py
```

介面分成四個分頁，照順序用就對了：

| 分頁 | 做什麼 |
|---|---|
| **主控台** | 從下拉選單挑遊戲視窗 → 按「使用此視窗」；之後用「啟動/停止」控制自動遊玩，看即時 log 與今日統計 |
| **校準** | 已內建從截圖量好的預設框選。可直接用，或按「套用截圖預設框選」還原；對不準再逐項微調 |
| **點數/花色樣板** | 在選牌畫面按「讀取目前畫面」→ 程式自動切出五張牌的左上角並猜出牌面 → 確認/修正代號 → 按「全部儲存」。右邊顯示點數 x/13、花色 x/4 的進度 |
| **設定** | 調整辨識門檻、策略參數等 |

第一次使用可以先勾「除錯模式」並打開「顯示即時辨識結果」，確認畫面狀態與手牌辨識
沒問題後再取消勾選、正式點擊。注意：每次按「啟動」都會依**當下**的勾選狀態套用，
取消勾選後若沒重新啟動，不會自動變成會點擊。

啟動後遊戲視窗要保持在最前面。熱鍵 **F9** 啟動/停止、**F10** 緊急停止在 GUI 中同樣有效。

## 做一個給別人用的安裝程式

要把整套工具交給沒有 Python 的人，就打包成單一安裝檔。對方雙擊、選資料夾、按
Install 就好，**不需要裝 Python，也不需要裝任何其他東西**（Python 直譯器、OpenCV
這些都已經包在裡面）。

### 你這台打包機要準備的（只做一次）

1. **Inno Setup 6**（免費，約 5MB）：<https://jrsoftware.org/isdl.php>
   下載 `innosetup-6.x.x.exe`，一路 Next 裝完即可。
   *想要中文安裝畫面的話*，另外到 <https://jrsoftware.org/files/istrans/> 抓
   `ChineseTraditional.isl`，丟進 Inno Setup 的 `Languages` 資料夾；沒有的話
   安裝畫面會是英文（只有 Next / Install / Finish 幾顆按鈕）。
2. **圖示**：把要當圖示的圖片存成 `icon.png` 放在專案根目錄。
   打包時會自動用 `make_icon.py` 轉成多尺寸的 `icon.ico`，exe 與安裝檔都會套用。

### 打包

```powershell
cd F:\holotool
app\.venv\Scripts\python.exe app\packaging\build_installer.py
```

它會依序做：產生圖示 → PyInstaller 打包 → Inno Setup 壓成安裝檔，最後產出

```
app\dist\HoloToolSetup.exe      ← 要拿給別人的就是這一個
```

常用參數：

| 參數 | 用途 |
|---|---|
| `--skip-build` | 跳過 PyInstaller（剛打包過、只想重做安裝檔時用，快很多） |
| `--version 1.2.0` | 指定版本號（顯示在控制台的「安裝的應用程式」裡） |

### 安裝程式的行為

- **預設裝到 `%LOCALAPPDATA%\HoloTool`**，安裝畫面可以自己改路徑。
  不預設 `C:\Program Files` 是有原因的：這個程式會把校準檔、樣板、log 寫在
  **自己旁邊**，裝在唯讀的位置一開啟就會出錯。安裝程式會在按下 Install 之前
  實際試寫一個檔，選到沒權限的資料夾會直接擋下來並提示。
- 自動建立開始選單捷徑；桌面捷徑可勾選。
- 控制台的「安裝的應用程式」裡有「解除安裝」。
- **你的校準與樣板（`app\config\config.json`、`card_templates\`）是打包在安裝檔裡面的。**
  你只要給對方 `HoloToolSetup.exe` 一個檔，其他什麼都不用另外傳；
  對方裝完這些東西就直接躺在他的資料夾裡，遊戲視窗長寬比一樣的話連校準都免了。

  這兩份標成「已存在就不覆蓋」，**只在重複安裝時才有差別**：
  對方裝了 v1、自己重新校準過，之後你給他 v2 —— 程式碼會更新成新的，
  但他調好的校準與自己抓的樣板不會被你的蓋回去，解除安裝時也不會被刪。
  第一次安裝時他的資料夾是空的，所以一定會完整放進去。
- 你的 `data\`（統計、每日達標次數）與 `logs\` **不會**被打包進去 ——
  那是你自己的紀錄，對方應該從零開始算。

> 💡 打包腳本會先把 `app\dist\HoloTool\` 裡比較新的校準與樣板**搬回專案根目錄**再打包。
> 這一步很重要：PyInstaller 的 `--noconfirm` 會把整個 `app\dist\HoloTool\` 砍掉重建，
> 不先搬走的話，你在 exe 那邊蒐集的樣板會在打包當下全部消失。
> 保險起見它也會另外留一份 `app\dist\HoloTool_backup\`。

## 版本號與自動更新

### 版本號只有一個來源

`app\src\version.py` 的 `__version__`。要發新版就只改這一行：

```python
__version__ = "1.0.1"
```

改完之後這三邊會自動跟著變：GUI 主控台顯示的版本、`build_installer.py` 產生的
安裝檔版本、`make_release.py` 的更新包檔名與更新檢查的比對基準。

> `__version__` 跟 `config.py` 的 `CONFIG_VERSION` **是兩件不同的事**，不要混用。
> 前者是「程式的版本」，後者是「設定檔結構的版本」。程式改了十次但設定檔格式
> 沒動，`CONFIG_VERSION` 就不該動 —— 一動就會讓 `RETUNED_ON_UPGRADE`
> 無謂地覆蓋掉你調過的參數。

同一個檔案裡還有更新來源：

```python
GITHUB_OWNER = "sumy1002"
GITHUB_REPO = "holotool"
```

### 使用者這邊怎麼更新

主控台分頁 →「版本與更新」→ **檢查更新**。

1. 只向 GitHub 問「最新的正式 Release 是哪一版」，不下載任何東西
2. 有新版就跳出說明，你按確認才會繼續
3. 下載 → 校驗 SHA256 → **備份你的校準與樣板** → 解壓到系統暫存區
4. 再問一次「要現在重新啟動嗎」，按是之後程式關閉、外部批次檔置換、自動重開

沒有網路、repo 打錯、GitHub 擋請求時只會在那一行顯示紅字，不會影響其他功能。

### 發一個新版（你這邊要做的）

```powershell
cd F:\holotool
# 1. 先改 app\src\version.py 的 __version__
# 2. 打包 + 產生更新包 + 算 SHA256
app\.venv\Scripts\python.exe app\packaging\make_release.py
```

跑完會產生兩個檔並印出後續步驟：

```
app\dist\HoloTool-1.0.1.zip
app\dist\HoloTool-1.0.1.zip.sha256
```

到 GitHub → Releases → **Draft a new release** → tag 填 `v1.0.1` →
把上面兩個檔拖進 Attach binaries → Publish。發布完成，舊版按「檢查更新」
就會看到。

> 想先自己試裝就把 Release 勾成 **pre-release** —— GitHub 的
> `releases/latest` 端點會跳過 pre-release，所以別人按檢查更新不會看到它。
> 試完再取消勾選。

第一次安裝的人要的是安裝檔，加 `--installer` 會順便產生
`HoloToolSetup.exe`，可以一起放上 Release。

### 更新絕對不會動到的東西

`config\`、`card_templates\`（含 `parts\`）、`data\`、`logs\`、`debug_captures\`。

這件事有**三層**保險，任何一層失效都還有另外兩層：

| 層 | 在哪裡 | 做什麼 |
|---|---|---|
| 1 | `make_release.py` | 更新包裡連這些資料夾都不放進去，而且打包完會自我檢查，發現有就刪掉 zip 並中止發版 |
| 2 | `updater.extract_update()` | 解壓時再過濾一次（也擋 zip 路徑穿越） |
| 3 | 置換用的 `.bat` | `robocopy` 帶 `/XD` 排除，而且**沒有** `/PURGE` 也沒有 `/MIR` |

加上更新前一定會先壓一份 `backups\pre-update-<版本>-<時間戳>.zip`，
**保留最近 5 份**才輪替刪除（只留一代等於白備份 —— 下一次動作就會把唯一
那份好的蓋掉，這個坑踩過了）。

### 為什麼一定要靠外部批次檔

**執行中的 exe 不能覆蓋自己**，Windows 會把檔案鎖住。所以流程是
「下載到暫存 → 解壓 → 關掉主程式 → 由 `.bat` 完成置換 → 重新啟動」，
Python 這一端從頭到尾不去寫 `HoloTool.exe`。

那支批次檔會先用 `tasklist` 等主程式的 PID 真的消失（最多 60 秒）才動手，
過程寫在 `app\logs\update.log`，更新出問題就先看這個檔。
批次檔內容**一律只用 ASCII** —— cmd 預設不是 UTF-8，帶中文的批次檔在某些
機器上會整行解析失敗，非常難查。

### 開發模式不支援自動置換

直接跑 `gui.py` 時「檢查更新」還是會告訴你有沒有新版，但不會自己置換檔案
（沒有 exe 可以換）。原始碼請用 `git pull`。

## 這個專案與 GitHub

repo 是**公開**的，所以自動更新的下載不需要任何 token，`HoloTool.exe` 裡
也沒有藏任何憑證。

### 什麼進版控、什麼不進

| | 進版控 | 說明 |
|---|---|---|
| `gui.py`、`app\src\`、`app\tools\`、`app\packaging\`、`app\tests\`、`app\docs\` | ✅ | 程式碼與文件 |
| `app\defaults\` | ✅ | 內建預設樣板，屬於程式內容 |
| `app\config\config.json` | ❌ | 你逐格校準的座標，綁著你自己的視窗解析度，對別人沒用 |
| `app\card_templates\` | ❌ | 你在實機抓的樣板。**這是重點** —— 一旦進版控，任何 `git pull` / `git checkout` 都有機會蓋掉它 |
| `.venv\`、`dist\`、`build\`、`logs\`、`data\`、`debug_captures\`、`backups\` | ❌ | 環境、產物、紀錄 |

> `app\defaults_layout.py` 已經帶著你在 1843×778 量出來的比例值
> （五格手牌是逐格量的，間距並不等寬），所以就算不把 `config.json` 進版控，
> 重灌或別人第一次裝也會拿到相當接近的預設框選。

### 想把自己抓的樣板分享出去

別直接把 `card_templates\` 加進版控。用這支工具**複製**一份到
`app\defaults\parts\`（那是程式內容，會進版控也會進更新包）：

```powershell
app\.venv\Scripts\python.exe app\tools\promote_templates.py           # 先預演，不動任何檔案
app\.venv\Scripts\python.exe app\tools\promote_templates.py --apply   # 確認後真的複製
```

複製過去時會改名成 `rank_2_b1.png` 這種帶 `b` 的編號，讓你原本那些檔案繼續
被歸類成「你自己的樣板」，辨識行為完全不變。之後別人裝好時，
`install_default_parts(overwrite=False)` 會把它們複製到他的
`card_templates\parts\` —— **不會蓋掉他自己抓的任何東西**。

> 目前 `card_templates\parts\` 裡還全部都是內建那批的複本
> （之前有個 bug 讓花色一張都存不進去）。先在 GUI 把四個花色重新存一次，

## 命令列使用方式（進階）

> 任何時候不確定進度，就執行這個指令看目前狀態：
>
> ```powershell
> app\.venv\Scripts\python.exe app\tools\check_setup.py
> ```
>

### 第 1 步：校準座標

1. 手動把遊戲開到「High & Low 牌桌畫面」（可以看到開始/下注按鈕的畫面）。
2. 執行：

   ```powershell
   app\.venv\Scripts\python.exe app\tools\calibrate.py
   ```

3. 依畫面指示輸入遊戲視窗標題關鍵字，然後依序框選/點擊：
   - 牌桌標記區域（一塊只有在這個牌桌畫面才會出現的獨特小區塊，例如標題文字/圖示）
   - 5 張手牌區域（門票關卡）
   - 比大小環節目前亮牌的區域
   - 開始/下注、確認換牌、大、小、收集/兌現 按鈕
   - 5 張手牌各自的「保留/丟棄」切換點擊位置（多數遊戲點卡面本身就能切換）

校準結果會存到 `config/config.json`，可以直接用文字編輯器打開微調數值。

**關於視窗大小**：所有座標都以「比例值 (0~1)」儲存，代表相對於視窗寬/高的百分比位置，
所以校準完之後你可以**自由移動與縮放視窗**，不需要重新校準，程式會依視窗當下的
實際尺寸即時換算。但要注意：

- **長寬比必須維持一致**。長寬比一改變，遊戲本身的 UI 排版通常也會跟著變動，
  比例座標就對不上了。程式在按下 F9 時會比較目前長寬比與校準時的差異，
  超過 `aspect_ratio_tolerance`（預設 2%）就會在 log 發出警告。
- **不要縮得太小**。視窗越小，每張牌的像素越少，不同牌的樣板分數會越靠近而難以區分。
  建議讓每張牌至少保有 60～80 像素寬；縮到校準時的 0.6 倍以下時程式也會提醒你。
- **不能最小化，也不能被其他視窗蓋住**，因為程式是直接讀取螢幕上那塊區域的像素。

### 第 2 步：蒐集點數與花色樣板

工具是用「讀卡片左上角的點數 + 花色」來辨識牌面，所以**不必蒐集 52 張整卡**，
只要湊齊 **13 個點數 + 4 個花色 = 17 個小圖**，全部 52 張牌就都認得出來。
一手牌就有 5 張，玩個一兩局大概就齊了。

推薦用 GUI 的「點數/花色樣板」分頁：

1. 玩到選牌畫面（五張牌正面朝上）
2. 按「讀取目前畫面」——程式會自動把五張牌的左上角切出來，並用現有樣板猜出牌面
3. 猜對的直接留著，猜錯或空白的自己填（例如 `10H`、`AS`、`QD`）
4. 按「全部儲存」

存數字牌時，程式會**額外把卡面中央那個大花色圖案也存起來**。角落那顆花色只有
十幾像素，黑桃和梅花常常只差 0.01 分；中央那個大三四倍，是把兩者分乾淨的關鍵。

> 專案已內附一組從截圖做出來的預設樣板（12 個點數 + 4 個花色，只缺「5」），
> 第一次執行會自動複製到 `card_templates/parts/`。可以直接開始用，
> 但**強烈建議在自己的實機畫面重新蒐集一輪**，準確度會明顯提升。

#### 內建樣板 vs 你自己抓的樣板

內建樣板是從 512～1024 寬的縮圖放大來的，筆畫比實機糊一圈。混在一起比對時，
糊掉的「7」有可能比清楚的「2」更像你螢幕上那個 2 —— 這就是「2、5、8 一直跳問號」
和「黑桃梅花分不清」的來源。

所以程式現在會分開看：**只要某個點數／花色已經有你自己抓的樣板，那個標籤的內建樣板
就整組不用**，還沒抓到的標籤才退回內建的頂著。「蒐集進度」那一欄會直接列出
「還在用內建樣板」的是哪幾個，右邊檔案清單也會在內建檔名後面標「（內建）」。

全部抓齊之後可以按「清掉所有內建樣板」把它們一次刪光（你自己抓的不會動）。

> ⚠️ 2026-08-20 修掉的一個老 bug：內建樣板每個花色剛好 8 張，而「同一個標籤最多留
> 8 張」的上限把內建的也算進去 —— 於是花色**一開始就是滿的**，按幾次「全部儲存」
> 都不會存下任何花色，畫面還完全不報錯。點數只有 3~4 張內建所以存得進去，
> 症狀才會變成「點數會學、花色永遠學不會」。現在上限只算你自己抓的，
> 而且存自己的樣板時會順手把同標籤的內建檔刪掉。
> **如果你之前存過花色卻覺得沒效果，就是踩到這個，請再存一次。**

命令列版（舊的整張卡面比對，當備援用）：

```powershell
app\.venv\Scripts\python.exe app\tools\collect_templates.py
```

## 策略邏輯說明

- **選牌（門票關卡）**：點「要留下的牌」（出現「剩餘」），沒點的會被「替換」。
  對 32 種保留組合模擬換牌後「至少兩對」的機率。鬼牌 JK 當萬能牌。
- **過關後**：先點「點擊繼續」，再在「要挑戰嗎？」選「進行挑戰」或「取消」兌現。
- **比大小**：只能選「大」或「小」。畫面寫「數字相同時，再抽一次」，平手不計勝負。
  要不要繼續加倍是在贏了之後的對話框決定，不是在大/小畫面上。
- **機率估計**：採用貝氏平滑 —— 資料不足時退回標準 52 張牌均勻機率，資料越多
  越貼近「今天實際觀察到的出牌分布」，並用過去幾天的紀錄作為很弱的輔助參考。
  每日統計檔案存在 `data/stats_YYYY-MM-DD.json`，可以自行打開查看。

## 設定檔 `config/config.json` 常用欄位

| 欄位 | 說明 |
|---|---|
| `ace_high` | 比大小時 A 是否視為最大牌 |
| `part_min_score` | 點數/花色小樣板的比對門檻，預設 0.72（加了質心對位後真正在把關的是下面的領先幅度） |
| `part_min_margin` | 點數最高分需領先第二名多少才採信，預設 0.05 |
| `match_threshold` | （備援用）整張卡面比對的相似度門檻 |
| `min_match_margin` | （備援用）整張卡面比對的領先幅度門檻 |
| `calibration` | 校準當時的視窗尺寸，用來偵測長寬比是否改變（校準時自動寫入） |
| `aspect_ratio_tolerance` | 長寬比容許誤差，超過就警告，預設 0.02（2%） |
| `templates.capture_client_width` | **擷取六個畫面標記樣板時的視窗寬度**。樣板是點陣圖，比對前會依「目前視窗寬 ÷ 這個值」縮放；重新框選標記時會自動更新 |
| `marker_thresholds` | 六個畫面標記各自的比對門檻（牌桌/選牌/過關/翻倍/失敗/湊牌失敗） |
| `marker_pads` | 各標記往外擴張搜尋的量 `[左右, 上下]`，單位是該區域自身的寬/高比例 |
| `draw_prompt_soft_threshold` | 選牌文字分數只到這裡、但五張手牌都認得出來時，一樣算選牌畫面 |
| `exit_table_ticks` | 連續幾次看不到牌桌 logo 才判定已離開牌桌（預設 25，約 10 秒） |
| `draw_result_wait_sec` | 按完「替換」之後最多安靜等幾秒讓遊戲切畫面（預設 15）。這段期間不做任何判斷；超時也只是回到一般偵測，**不會**自己當成湊牌失敗 |
| `config_version` | 設定檔版本。升級時某些「重新調校過」的參數會強制換成新預設（目前是 `part_min_score` / `part_min_margin`），校準數值一律保留不動 |
| `daily_max_wins` | 每天可以達到「最高獲得金額」幾次（遊戲規則是 2）。達成次數記在 `data/stats_YYYY-MM-DD.json` 的 `max_win_count`，重開程式也不會重數；手動玩過導致次數對不上就直接改那個檔案 |
| `highlow_scan_right` | 比大小掃描「目前這張牌」時，往右掃到畫面的哪個比例位置為止 |
| `table_marker_threshold` | 舊欄位，已由 `marker_thresholds.table_marker` 取代 |
| `monte_carlo_samples` | 選牌策略模擬次數，越大越準但越慢 |
| `highlow_min_win_prob_to_continue` | 比大小勝率低於此值就收手兌現 |
| `highlow_max_chain` | 比大小最多連續加倍幾次 |
| `capture_interval_sec` | 主迴圈偵測間隔秒數 |
| `action_cooldown_sec` | 點完之後至少等多久才做下一個動作（預設 1.2 秒）。遊戲跑得慢就調大 |
| `action_retry_sec` | 同一個畫面卡多久沒變，就視為遊戲漏收點擊而再點一次（預設 2.5 秒） |
| `idle_confirm_sec` | 畫面要連續認不出來多久，才會去點「投注並開始」（預設 1.5 秒） |
| `multi_click_gap_sec` | 選牌時連點五張牌，每一下之間的間隔（預設 0.18 秒） |
| `click_hold_min_sec` / `click_hold_max_sec` | 滑鼠按下到放開的停留時間（預設 0.06~0.12 秒） |

## 已知假設 / 之後可能需要調整的地方

因為我沒有你實際的遊戲畫面，下列邏輯是根據你描述的規則所做的假設，實際測試後
若發現跟遊戲行為不符，歡迎直接告訴我，我可以再調整程式：

1. **換牌次數**：目前假設「門票關卡只能換一次牌」（發5張→選保留/丟棄→補牌後直接
   定局）。若實際上可以換多次，需要調整 `_handle_draw_phase` 的流程。
2. **確認/前進按鈕**：換完牌之後如果需要額外按一次「確認」才能進入比大小畫面，
   目前程式重複使用 `draw_confirm` 這個按鈕，若實際上是不同按鈕，需要在
   `config.json` 的 `points` 裡新增並修改 `src/bot.py` 對應的呼叫。
3. **比大小平手規則**：目前策略只單純比較「比較大」與「比較小」哪個機率高，
   沒有特別處理「平手」時的規則（平手算贏/輸/和局尚不確定），必要時可在
   `src/strategy.py` 的 `decide_high_or_low` 調整。
4. **是否為固定52張牌無重複抽取**：換牌模擬時假設「目前看到的5張牌」在這一輪
   內不會重複出現（無重複抽取），但比大小的機率估計則是用「今天觀察到的頻率」
   獨立估計每張牌出現機率（不特別排除已出現過的牌），這是因為你希望依實際出牌
   頻率推算機率、而非假設固定的實體牌堆。
5. **每日上限偵測**：主要靠「已達最高獲得金額，遊戲結束」這一行字（`max_win_marker`），
   第 1 次自動按「再玩一次」、第 2 次自動停止。「牌桌標記區域消失」則保留為備援。
   ⚠️ 這個標記**沒有內建預設樣板**（我手上沒有那個畫面的原始截圖），
   要自己在「校準」分頁校準過才會生效，`app\tools\check_setup.py` 會提醒你。
6. **縮放後的辨識能力**：牌面辨識是讀左上角的點數與花色，會依卡片實際大小自動
   換算，所以縮放沒問題；但視窗太小時字會糊掉。建議每張牌至少留 60~80 像素寬。
7. **比大小剛翻牌的瞬間**：那一張會放大並超出校準框，這個過渡畫面會回報「認不出來」，
   等它落回牌列後才讀得到。這是刻意的：寧可等 0.4 秒，也不要讀錯牌。

## 疑難排解

### 先跑這兩個指令

```powershell
app\.venv\Scripts\python.exe app\tools\check_setup.py                          # 還缺什麼
app\.venv\Scripts\python.exe app\tools\check_markers.py app\debug_captures    # 六個標記各拿幾分
```

`app\tools\check_markers.py` 是離線工具，不用開遊戲，拿現成截圖就能算出每個畫面標記的分數，
右邊標 `*` 代表超過門檻。可以加 `--width 1937` 模擬「實機視窗這麼寬時的分數」。

### 常見狀況

- **畫面標記全部認不出來（分數都在 0.4~0.7 徘徊）**：多半是**樣板解析度和實機視窗
  對不上**。內建預設樣板是從 1024×438 的截圖切出來的；如果你的遊戲視窗是
  1937×817，樣板要放大 1.89 倍才對得起來。程式會依
  `templates.capture_client_width` 自動換算，但這個值必須正確。

  最乾淨的做法：在「校準」分頁對著實機畫面**逐項重新框選**六個畫面標記
  （框完當下就會用目前解析度重存樣板，並自動更新這個欄位）。

  ⚠️ 重存之後**不要再按「套用截圖預設框選」**，那顆按鈕會把樣板整組還原成
  1024 寬的內建預設圖，等於白做。

- **對話框停久了就自動停止、說「已達每日次數上限」**：翻倍/成功/失敗這些對話框會把
  整個牌桌連同左上角 High&Low logo 一起模糊掉，logo 認不出來是正常的。程式已經會在
  偵測到任一對話框時重置離桌計數器；若還是誤判，把 `exit_table_ticks` 調大。

- **湊牌結果畫面有時認得、有時認不得**：那個位置的大標題是會變的
  （失敗／無對子／一對／兩對…），所以不能只靠 `fail_marker`。真正不變的是副標
  「要再玩一次撲克嗎？」，也就是 `poker_fail_marker`。若這個標記分數偏低，
  優先重新框選它。

- **程式以為點了、但遊戲沒反應，然後就卡住不動**：遊戲跑得比程式慢時會漏收點擊。
  程式現在會在同一個畫面卡超過 `action_retry_sec`（預設 2.5 秒）時自動再點一次，
  log 會出現「[重試] 畫面還停在…」。如果還是常常卡住，依序調整：
  1. `click_hold_min_sec` / `click_hold_max_sec` 調大（例如 0.10 / 0.20）——
     讓滑鼠按住的時間橫跨更多幀，這通常最有效
  2. `action_retry_sec` 調小（例如 1.8），卡住時更快補點
  3. `multi_click_gap_sec` 調大（例如 0.30），選牌那五下之間留更多時間

- **明明湊到牌了，卻跳「湊牌失敗」把那一局打掉**：舊版會在按完「替換」之後等 2.5 秒，
  沒看到過關畫面就自己認定湊牌失敗。遊戲慢一點就會誤判。現在**只認
  「要再玩一次撲克嗎？」這個標記**，看不到標記就安靜等（最多
  `draw_result_wait_sec`，預設 15 秒），超時也只是回到一般偵測，不會亂點。

- **某幾個點數一直跳問號（常見於 2、5、8），或黑桃梅花分不清**：
  1. 先看「點數/花色樣板」分頁的「蒐集進度」，有沒有標「還在用內建樣板」。
     有的話在實機畫面抓一次自己的，程式會自動改用你的。
  2. 程式會同時讀**左上角和右下角**兩個角落（撲克牌的點數花色一定印兩次），
     兩次分數平均之後雜訊會互相抵銷。比大小畫面的牌被疊住、只露左上角時
     會自動退回單角判讀，log 會註明「只讀得到左上角」。
  3. 還是不行就把 `part_min_margin` 調小一點（例如 0.03）。

- **會多點一下「投注並開始」，把畫面弄亂**：那是遊戲在跑動畫、畫面暫時認不出來時
  被誤判成待機。把 `action_cooldown_sec` 或 `idle_confirm_sec` 調大（例如 2.0）。

- **達到上限了卻沒自動停／沒按「再玩一次」**：先跑 `app\tools\check_setup.py` 看
  「已達最高獲得金額標記」是不是還沒校準。校準時要框**底部中央那一行字**
  （「已達最高獲得金額，遊戲結束」），不要框到旁邊的按鈕；右下角那顆「再玩一次」
  的位置跟失敗畫面那顆不一樣，要另外校準 `max_win_retry`。

- **今天的達成次數算錯了**（例如自己先手動玩過一次）：打開
  `data/stats_YYYY-MM-DD.json`，把 `max_win_count` 改成正確的數字即可。

- **按「檢查更新」說找不到 repo（HTTP 404）**：`app\src\version.py` 的
  `GITHUB_OWNER` / `GITHUB_REPO` 打錯，或那個 repo 還沒發過任何 Release。
  用瀏覽器開 `https://github.com/<OWNER>/<REPO>/releases` 確認一下。

- **按「檢查更新」說 GitHub 擋住請求（HTTP 403）**：未登入的 API 查詢每小時有
  次數上限。等一小時，或直接到 Release 頁面手動下載。

- **更新按完重開，版本還是舊的**：看 `app\logs\update.log`。
  常見兩種：`pid ... still alive after 60s`（主程式沒有真的關掉 —— 通常是還有
  另一個 HoloTool 視窗開著）、`robocopy exit code ...`（安裝目錄沒有寫入權限，
  例如裝在 `C:\Program Files` 底下）。兩種都不會動到你的校準與樣板，
  重跑一次或改用安裝檔手動更新即可。

- **更新之後想確認校準沒被動到**：看 `app\backups\` 裡最新那個
  `pre-update-*.zip`，跟現在的 `config\config.json`、`card_templates\parts\`
  比一下。備份留最近 5 份，要還原就直接解壓覆蓋回去。

- **F9/F10 沒反應**：改用系統管理員身分執行終端機。
- **辨識不到牌**：先跑 `app\tools\check_setup.py` 看「點數 x/13、花色 x/4」還缺什麼。缺的那些
  牌一定認不出來。接著用 `--dry-run` 模式觀察 log。可能是視窗縮太小導致各張牌分數
  太接近而被 `min_match_margin` 保護機制擋下（這是刻意設計：寧可辨識失敗也不要
  猜錯牌）。解法是把視窗放大一點，或補充更多卡牌樣板；真的要放寬才調低
  `match_threshold` / `min_match_margin`。
- **樣板都蒐集齊了，執行時卻只認出 2/5**：這是對位問題，不是樣板不夠。
  同一個點數在不同影格切出來的位置常常差一兩像素，重疊度就會掉 0.15~0.20 分。
  程式現在會先把字的「質心」對到畫布正中央，再做 ±1 像素的微調才比對 ——
  實測正解分數中位數從 0.78 拉到 0.97。
  現在辨識失敗時 log 會直接印出原因，例如：

  ```
  已看到選牌畫面，但手牌只認出 2/5，以下是認不出來的那幾格：
     第 3 張：點數 9=0.78  7=0.69 ←領先不足 0.05 | 中央大圖案(黑) C=0.95  S=0.93
  ```

  「←分數未達」就是缺那個點數/花色的樣板；「←領先不足」就是兩個候選太像，
  在「點數/花色樣板」分頁多存幾張那個點數即可。

- **黑桃 / 梅花會搞混**：這兩個花色的角落小圖案最難分。解法是在「點數/花色樣板」
  分頁多存幾張**數字牌**（2~10、A），程式會一併存下卡面中央的大圖案，那個分得很開。
  同一個點數/花色最多留 8 張樣板，比對時取最高分。
- **常常認錯點數**：把視窗放大，並在「點數/花色樣板」分頁多存幾組。
- **點擊點錯位置**：確認長寬比沒有被改變（縮放沒問題，長寬比改變才有問題）；
  如果調整過遊戲解析度或長寬比，需要重新執行 `calibrate.py`。
- **滑鼠亂跑/誤觸**：把滑鼠移到螢幕任一角落即可透過 pyautogui 防呆機制強制停止，
  或按 F10 緊急停止。
